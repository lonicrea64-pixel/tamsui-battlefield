# 淡水古戰場互動地圖 MVP 規格

## 1. 待確認項目（資訊不足不硬猜）
- 歷史內容是否需要學者或地方文史單位最終審校。
- 產品正式品牌名稱與對外語言版本（僅繁中或含簡中/英文）。
- 上線環境（自架雲主機、Vercel + Render、或機關內網）以決定 CI/CD 與監控方案。

## 2. 使用者與核心任務
- 主要使用者：想了解歷史的人、想了解淡水的人。
- 核心任務：在地圖上選一個古戰場點位，快速理解其歷史角色並完成一次學習回饋。

## 3. MVP 範圍
- 內含：清法戰爭淡水戰役的古戰場點位、時間線、單題互動學習回饋。
- 不做：社群聊天、付費訂閱流程、跨校管理後台。

## 4. I/O 規格化
- 輸入：
  - `GET /api/v1/sites?lang=...`
  - `GET /api/v1/sites/:siteId`
  - `GET /api/v1/timeline`
  - `POST /api/v1/learning-check` `{ siteId, answerId }`
- 輸出：
  - 統一成功格式：`{ data: ... }`
  - 統一錯誤格式：`{ error: { code, message, details } }`

## 5. 限制與非功能需求
- 回饋時效：核心 API 在一般網路條件下應於 3 秒內完成回應。
- 穩定性：非法輸入必須回傳可理解錯誤，不得造成服務崩潰。
- 裝置相容：手機與桌機皆可完成核心流程。
- 可維護性：使用 TypeScript、明確資料模型、API 契約文件、測試案例。

## 6. 反需求
- 第一版不提供帳號系統與個人化推薦。
- 第一版不提供即時聊天室。
- 第一版不提供後台內容管理介面。

## 7. 情境式驗收（Given-When-Then）
- Given 使用者進入首頁，When 點選任一古戰場並送出答案，Then 3 秒內看到正確/錯誤回饋與下一步引導。
- Given 使用者送出非法 `siteId` 或 `answerId`，When API 接收請求，Then 回傳可理解錯誤訊息且系統不崩潰。
- Given 手機與桌機環境，When 執行核心流程，Then 互動與版面皆可正常使用。
